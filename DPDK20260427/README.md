# 广域网新优化方案需要的修改和相关重点：
1、增加在连接缓存结构体中新增NAK缓存*mbuf，不需要复杂判断，只需要收到NAK后存入就行，生命周期是确认源网关收到扩展NAK报文（判断条件是：3次扩展NAK发送后还没有收到重传报文，这时超时清除 || 目的网关收到重传报文，或者SR重传完成，SR重传标志置位后）
2、所有的重传（网关间的SR重传、目的网关与目的DCI间的GBN重传）都是先设置高性能1ms定时器（等定时器结束才开始重传），每次收到数据报文就重置1ms。也就是等数据报文发完了，再进行重传
3、网关从原本的外挂式网关（用旁路缓存），改成串联式。也就是把网管串联进网络通路里
4、不再设置网关role，而是使用扩展NAK。只有目的网关收到目的主机的NAK，源网关只会收到目的网关加工过的扩展NAK（具体丢包处理流程看ppt）


## 一、方案核心重点总结（导师宣讲核心要求）

1. 部署方案定论
废弃 DCI 旁路部署：现网 DCI 无法逐包识别 RoCEv2、重定向性能损耗大，不可行。
确定最终架构：双网卡 DPDK 网关串联部署（部署在数据中心出口交换机↔路由器之间），网卡 1↔网卡 2 双向转发。

2. 核心要解决的问题
广域网下RoCEv2 RC 端到端重传闭环太长：
丢包后端主机触发 GBN 全量重传，时延 50ms~100ms+；
端主机必须等对端 ACK 才能发新包，发送速率极低；
重传报文重复、链路利用率低。

3. 核心改进方案（核心创新点）
网关间缩短重传闭环：端→端 → 网关↔网关
自定义扩展 NAK 报文（网关间私有协议，不修改端主机 RoCEv2 协议）；
扩展 NAK 携带多丢包段（start_psn+end_psn），支持 SR 选择性重传；
网关自适应角色：无需静态配置源 / 目的网关，靠 NAK 类型自动区分；
重传策略：SR（多丢包段）+GBN（兜底）结合。

4. 报文处理规则
报文类型 网关处理逻辑
数据报文 先缓存→再转发
ACK 报文 清理对应 PSN 缓存→转发
原始 NAK 目的网关处理：有缓存→延时 GBN；无缓存→构造扩展 NAK 发给源网关
扩展 NAK 源网关处理：有缓存→SR 重传；无缓存→还原为原始 NAK 发给端主机
CM 报文 解析 CONNECT/DREQ→建 / 删流表 + 连接表→转发
其他报文 直接转发

5. 关键技术要求
扩展 NAK 报文格式：BTH + 自定义扩展头（多丢包段）+AETH，仅在网关间传输；
1ms 延时定时器：聚合 NAK、避免频繁发扩展 NAK，收新包复位定时器；
连接跟踪：监控 CM 报文，维护 QP 状态（INIT→ESTABLISHED→DISCONNECTED）；
连接老化：超时规则max(3×RTO, 2×RNR_TIMER)，RCU 安全释放资源；
无角色配置：网关自动识别源 / 目的角色，不依赖静态配置。

6. 要修改 / 实现的核心模块
双网卡 DPDK 串联转发；
扩展 NAK 报文构造 + 解析；
1ms 延时定时器（NAK 聚合）；
SR 选择性重传（多丢包段）；
CM 报文解析（建连 / 断连）；
连接状态机 + 自适应角色；
兼容现有缓存 / 老化 / RCU 释放逻辑。

7. 核心验收标准（导师要求）
✅ 网关串联部署，双网卡无损耗转发；
✅ 广域丢包时，网关间发扩展 NAK，触发 SR 重传；
✅ 无需配置网关角色，自动识别；
✅ CM 报文自动建 / 删连接；
✅ 重传闭环缩短为网关↔网关，时延降低 80%+；
✅ 无内存泄漏、RCU 安全释放；
✅ 兼容标准 RoCEv2 协议，端主机无修改。


## 仅缓存模块的改进重点（你负责的部分，完全剔除重传相关）
我已从导师 PPT 中剥离所有重传、扩展 NAK、SR/GBN、定时器触发重传等无关内容，只保留你负责的「缓存模块」核心改进要求，精准匹配你的工作范围：

1. 导师要求缓存模块的核心改进规则
缓存触发严格绑定报文类型（强制执行）
数据报文：先缓存、再转发（缓存是第一步，不可跳过）
ACK 报文：先按 PSN 清理已确认缓存、再转发 ACK
原始 NAK 报文：仅查询本地缓存是否存在对应 PSN（只查缓存，不做任何重传）
CM 建连报文：初始化连接缓存空间
CM 断连报文：立即销毁该连接所有缓存资源
其他报文：不缓存、直接转发
缓存生命周期升级（动态管理）
建连 → 初始化缓存、重置 PSN 区间
断连 → 全量清空缓存、释放所有 mbuf
ACK 确认 → 精准清理 **<=ACK PSN** 的缓存（兼容 24 位 PSN 回绕）
异常断开 → 老化线程自动清理缓存
缓存老化规则升级（从固定时间→动态时间）
原：固定 500ms 老化
新：按连接自身 RTO 动态计算 → 老化时间 = max(3×RTO, 2×RNR_TIMER)
缓存安全释放强化
配合 RCU 延迟释放，杜绝 mbuf 野指针、内存泄漏
断连 / 老化时批量全量清理连接缓存
缓存状态绑定连接状态
仅ESTABLISHED（已建连）状态允许缓存报文
INIT/DISCONNECTING状态禁止缓存

2. 你现有缓存模块的缺失点
无连接状态判断，任何状态都能缓存
无CM 建连 / 断连的缓存初始化 / 销毁逻辑
无原始 NAK 的缓存查询接口（只查不重传）
老化时间是固定值，未按 RTO 动态计算
ACK 清理缓存未完全兼容 24 位 PSN 回绕
无异常断开的缓存全量清理逻辑
