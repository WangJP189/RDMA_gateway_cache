## 1. 已完成实验详解

### 1.0 被评估的机制：psn_dynblock

三个基线缓存方法与我们的机制，都是为 **RDMA 网关的重传缓存（retransmission cache）** 服务的：网关收到下游丢失的 PSN 后，用缓存里暂存的 payload 完成重传，避免回源。

**我们的机制 `psn_dynblock`（PSN 确定性映射 + 动态内存块）核心：**

- **位置映射**：`Φ(psn) = (psn & 0xFFFFFFu) % N`（24-bit 归一化 + 取模）。O(1)：一次取模 + 一次槽元数据读 + 一次 PSN 比较，无指针追逐。
- **环长 N**：N = 重传窗口长度 = in-flight 包数上界（`N ≥ ceil(link_rate_gbps × RTT_ms / MTU_B) × safety`）。当前 `CFG_RING_N = 10240`（≈100 Gbps × 3 ms RTT @ 4096 B，跨洲 WAN），**故意非 2 的幂**。
- **块大小 S**：`S = ceil_class(cfg, MTU)`，取 `SC_NEW` 27 档 `{128,256,…,2048,2304,…,4096,5120,6144,8192}` 中 ≥ MTU 的最小档。槽步长 `stride = align16(24 + S)`（24 是包头 `mem_block_header` 的大小）。
- **自适应 resize**（每满 N 个 store 检查一次，无时间兜底）：
  - **规则 A（扩）**：`ovf_count ≥ ovf_thresh(256)` 且连续 `k_dwell(2)` 个纪元 → 扩到 `ceil_class(L_ovf)`。另有**紧急路径** `grow_locked`（溢出数组打满 ovf_cap=2048 时立即扩）。
  - **规则 B（缩）**：`quiet_epochs ≥ j_quiet(4)` 且 `shrink_streak ≥ k_dwell(2)` 且 `L_ring ≤ 0.75·S` → 缩到 `ceil_class(L_ring)`（且不低于历史溢出包档）。
- **双世代零迁移切换** `gen_switch`：扩/缩时分配新池、旧池挂为 `old`，旧池随位置淘汰自然排空（`old_live` 递减到 0）后释放；O(1) 计数，不搬数据。8-bit `gen` 回绕安全依赖「切换时旧池必须已排空」这一前置不变量。
- **内存**：环池 `mmap(MAP_NORESERVE)` 惰性提交（失败回落 malloc）；环路径稳态 **store 零 malloc**（不变量 I3）；只有放不下 S 的包走溢出（每项 malloc 变长块 `align16(24+len)`）。

**三个基线缓存方法（无界版 + 有界 `*_bounded` 版）** 与一个对照 E：

| 方法 | 结构 | 检索复杂度 | 淘汰（bounded 版） |
|---|---|---|---|
| FIFO Queue | 单链表，节点 32B+payload | O(N) 线性 | 淘汰 head |
| Chained Hash | 16384 桶链，节点 32B+payload，Knuth 乘法哈希 | O(1) 平均 | 位置淘汰 `psn%N`（同 Φ） |
| Balanced Tree | AVL，节点 56B+payload | O(log N) | 插入序 FIFO（指针直接摘除） |
| index_only（对照 E） | 只存 `psn%N` 槽，不拷贝 payload | Φ 纯算术 | 位置覆盖 |

`*_bounded` 是「对照 D」：预分配节点池 + 容量 N + 滑动淘汰，使**活集恒为 N ⇒ hash 负载恒 0.625**，与 psn_dynblock 唯一差异回到「索引结构」本身（消除「分配策略」与「活集大小」两个 confound）。`index_only` 给出位置映射的**不可约成本**（映射 + 槽命中，无 payload 拷贝），回答「取模不是免费的」。

### 1.1 exp1a_store —— 存时间开销

**实验目的 / 假设**：验证 PSN Mapping 的 store 时间开销假设——小包下略慢于 FIFO/Hash（多了取模 + 槽元数据写），大包下持平甚至更快（Hash/Tree 需 malloc/指针追逐，PSN 只 memcpy 进固定槽）。

**实验设置**：
- **方法（6）**：`fifo_bounded`、`chained_hash_bounded`、`balanced_tree_bounded`、`psn_dynblock`（弹性）、`psn_dynblock_fixed`（S=4096 固定）、`index_only`（对照 E）。
- **payload（5 档 RDMA MTU）**：256 / 512 / 1024 / 2048 / 4096 B。
- **N = 10240**（满窗），顺序 PSN 存储（存 0..N-1）。
- **计时**：裸 `rdtsc` 批量摊销——每批 B 次 store 夹一对 rdtsc，`per-op = (t1-t0)/B`；主矩阵 **B=8192**（读钟 ~3.8μs 摊到 0.46ns/op，占最快方法 ~5.8%），**B=1024** 交叉验证（论证「floor ∝ 1/B」闭环）；`timed_ops=500000`，`reps=5`，样本跨 rep 池化。主指标 **p50**，次指标 **p90**（p99 受 VM ~2ms 调度停顿污染，仅 CSV 留痕）。
- **dynblock 口径（「收敛后冻结」）**：`psn_dynblock` 在预热期开 `adaptive_enable=1` 让 S 按机制自行收敛（256B→S=256、…、4096B→S=4096），记录收敛后 S，再 `adaptive_enable=0` 冻结计时；`psn_dynblock_fixed` 全程 S=4096 固定（「不做自适应」的对照）。
- **预热**：每个方法 store 路径的真实 malloc 尺寸类统一 `warm_allocator` 预热（见 `docs/R1_warmup_coverage.md`），消除冷分配器偏差。

**实验流程**：`make build/exp1a_store && ./build/exp1a_store` → 逐 (B × payload × 方法) 建缓存、预热（含 dynblock 收敛 S）、计时、落盘。

**实验结果（p50 ns，B=8192 主矩阵）**：

| method | 256 B | 512 B | 1024 B | 2048 B | 4096 B |
|---|---|---|---|---|---|
| FIFO Queue | 10.450 | 16.457 | 39.299 | 132.754 | 464.994 |
| Chained Hash | 11.952 | 18.447 | 45.855 | 138.175 | 473.735 |
| Balanced Tree | 90.403 | 92.637 | 102.453 | 227.504 | 554.909 |
| **PSN Mapping (adaptive S)** | 14.223 | 20.950 | 33.671 | 122.926 | **435.926** |
| PSN Mapping (fixed S=4096) | 19.765 | 32.865 | 90.269 | 247.758 | 432.752 |
| index-only (Φ) | 1.917 | 1.941 | 2.259 | 2.283 | 2.051 |

**收敛后 S**：弹性版 256B→256、512B→512、1024B→1024、2048B→2048、4096B→4096（各档精确命中）；固定版恒 4096。

**证明了什么**：
1. 小包（256B）PSN 弹性 14.2ns，慢于 FIFO 10.5ns / Hash 12.0ns（取模 + 槽元数据开销）；**大包（4096B）PSN 弹性 435.9ns 反超 FIFO 465.0ns / Hash 473.7ns 成为最快**——验证「小包开销高、大包持平/更快」的假设。
2. `index_only ≈ 2ns` 给出 Φ 映射 + 槽写的不可约下界，说明 PSN 相对 FIFO/Hash 的额外开销几乎全来自「取模 + 元数据」，而非 payload 拷贝。
3. 固定块 S=4096 存小包（256B→19.8ns、1024B→90.3ns）明显慢于弹性版（256B→14.2ns、1024B→33.7ns）——因为 4128B 槽只存 256B 破坏缓存局部性（→ 引出 exp2 的空间代价）。

**代码 / 数据 / 图位置**：
- 代码：`bench/exp1a_store.c`
- 数据：`out/exp1a_store/store_summary.csv`（原始）、`out/exp1a_store/exp1a_numbers.md`（脚本提取）、`out/exp1a_store/resolved_config.json`（复现配置）
- 图：`paper_figures/fig_exp1a_store.png` / `.pdf`（@300dpi）
- 绘图/提取脚本：`paper_figures/plot_exp1a_store.py`

### 1.2 exp1b_lookup —— 取时间开销

**实验目的 / 假设**：回答两个审稿疑问——① PSN 为何在旧数据里慢于 Chained Hash，重排序（reorder）成本是否被计入；② 根因是否为「块大小 S 与 payload 不匹配」。

**实验设置**：
- **方法（6）**：`fifo_bounded`、`chained_hash_bounded`、`balanced_tree_bounded`、`psn_dynblock`（S0=payload）、`psn_dynblock_adaptive`（S0=4096 预热收敛后冻结）、`index_only`。
- **模式（4，NAK 重传真实工作负载）**：GBN-long(64)、GBN-short(8)、SR-16、SR-64。
- **N（缓存深度 / 工作集条数，6 点）**：512 / 1024 / 2048 / 4096 / 8192 / 10240。
- **payload 只跑 1024**（范围收窄）；`B=512` 主 + `B=32` 交叉验证；`reps=5`。
- **计时单位**：一次 `retrieve_range` / `retrieve_set`（定位 + memcpy 全过程，即一次 GBN/SR 重传完整开销）；SR `reorder=1` 额外含「把 64 个 PSN 升序整理」。主指标 p50。
- **reorder 维度（2026-09-17 新增）**：GBN 输出天然有序（reorder 恒 0）；SR 跑 reorder∈{0,1} 两版对比。排序对所有方法对称（同一 64 元素升序插入排序，计时内）。
- **dynblock 口径**：`psn_dynblock` = S0=payload（等价于 CM 上报 MTU 的正确初始化）；`psn_dynblock_adaptive` = S0=4096 预热期收敛到 1024 再冻结（互证 S0=MTU 是正确初始化，且忠实于「收敛后冻结」）。

**实验结果（p50 ns，gbn_long64 reorder=0）**：

| method | 512 | 1024 | 2048 | 4096 | 8192 | 10240 |
|---|---|---|---|---|---|---|
| FIFO Queue | 23523.9 | 50899.5 | 95488.1 | 195959.6 | 454111.2 | 561597.7 |
| Chained Hash | 1508.0 | 1551.9 | 1642.6 | 1933.2 | 2204.5 | 2305.5 |
| Balanced Tree | 1722.7 | 1854.7 | 2146.1 | 2466.5 | 3093.7 | 3249.6 |
| PSN Mapping (S0=payload) | 1473.4 | 1508.0 | 1627.9 | 1814.5 | 2152.4 | 2279.6 |
| **PSN Mapping (adaptive S)** | 1505.4 | 1535.5 | 1566.0 | 1770.3 | 1936.9 | **2062.1** |
| index-only (Φ) | 251.8 | 225.0 | 238.5 | 261.7 | 270.3 | 276.2 |

**sr_64 @ N=10240**：reorder=0 时 Chained Hash 3116.0、PSN adaptive 3326.4、PSN S0=payload 3827.0、Tree 8229.8、FIFO 638947.1、index 251.6；reorder=1 时 Hash 4264.3、PSN adaptive 4401.3、Tree 8547.4、index 1283.3。

**reorder 增量（reorder=1 − reorder=0，p50 ns）**：
- sr_16 @ N=10240：Hash +105.9、Tree +130.5、PSN S0=payload +156.3、PSN adaptive +175.4、index +147.3（**~150ns，各方法同量级**）。
- sr_64 @ N=10240：Hash +1148.4、PSN adaptive +1074.9、index +1031.8（**~1050ns，各方法同量级**）。

**n_cmp（每次取包平均比较次数，gbn_long64 代表）**：FIFO ≈ N/2（512→255.5 … 10240→5123.4）；Chained Hash ≈ 1.0；Balanced Tree ≈ log N（8→12.4）；PSN Mapping 与 index-only = **0**（Φ 纯算术，无 PSN 比较）。

**证明了什么**：
1. **reorder 成本对所有方法对称**（sr_64 排序 ~1050ns、sr_16 ~150ns，与缓存结构无关）——reorder **不是** PSN 落后 hash 的根因。
2. **PSN 落后 hash 的根因是块大小 S 与 payload 不匹配**（旧 S=4096 存 1024B 包 → 4128B 槽 vs hash 节点 1056B → 缓存局部性惩罚）。修正为 **S=payload（S=1024，stride 与 hash 节点相同）后 PSN 反超 hash**：gbn_long64（2062 vs 2305）、gbn_short8（231.7 vs 276）、sr_16（662.6 vs 775.3）三处领先，仅 sr_64 差 ~7%（3326 vs 3116）。
3. `index_only ≈ 250ns` 给出 Φ 映射 + 槽读的不可约下界，`psn_dynblock` 与 `psn_dynblock_adaptive` 最终 S 都是 1024、结果一致，互证「S0=MTU」是正确的初始化。
4. FIFO O(N) 在 N=10240 下 ~0.5ms/op，验证其线性退化；PSN/Hash/Tree 均不随 N 显著增长。

- 数据：`out/exp1b_lookup/lookup_summary.csv`、`out/exp1b_lookup/n_cmp.csv`（原始）、`out/exp1b_lookup/exp1b_numbers.md`（脚本提取）、`out/exp1b_lookup/exp1b_analysis_data.md`、`out/exp1b_lookup/resolved_config.json`

### 1.3 exp2_space —— 空间利用率

**实验目的 / 假设**：回答「我们的利用率是否在最优基线约 5% 以内」，并证明「弹性槽大小」解决了固定内存块空间利用率低下的问题。

**实验设置**：
- **方法（5，全部有界预分配）**：`fifo_bounded`、`chained_hash_bounded`、`balanced_tree_bounded`、`psn_dynblock`（弹性 S=ceil_class(pl)=pl）、`psn_dynblock_fixed`（S=4096 固定）。无界版每 store malloc，不参与 exp2。
- **满窗 N = 10240**（= CFG_RING_N = CFG_E2_N，重传窗口上界）。
- **payload（5 档 MTU）**：256 / 512 / 1024 / 2048 / 4096 B。
- **指标**：`utilization = payload_bytes / allocated_bytes`；`payload_bytes = N × pl`；`allocated_bytes = cache_footprint_bytes(bc)`（池 + 索引/桶 + 元数据，全部 `sizeof()` 实测，不硬编码）。
- **流程**：每个 (payload × 方法) 填 N 条 `psn=0..N-1`（逐槽命中，无淘汰、无溢出、无 resize），断言 `n_malloc==0` 且 `n_resize==0`（满窗占用是纯静态量，与访问序列无关）。

**实验结果（空间利用率 %，满窗 N=10240）**：

| method | 256 B | 512 B | 1024 B | 2048 B | 4096 B |
|---|---|---|---|---|---|
| FIFO Queue | 88.89 | 94.12 | 96.97 | 98.46 | 99.22 |
| Chained Hash | 82.90 | 90.65 | 95.10 | 97.49 | 98.73 |
| Balanced Tree | 80.00 | 88.89 | 94.12 | 96.97 | 98.46 |
| **PSN Mapping (adaptive S)** | 84.43 | 91.56 | 95.59 | 97.75 | 98.86 |
| PSN Mapping (fixed S=4096) | 6.18 | 12.36 | 24.72 | 49.43 | 98.86 |

**与最优基线 FIFO 的差距（pp）**：256B 差 4.46、512B 差 2.56、1024B 差 1.38、2048B 差 0.71、4096B 差 0.36。**弹性最大劣势点 256B 差 4.46pp ≤ 5% 断言成立**；fixed 最大塌陷点 256B 只有 6.18%（vs FIFO 88.89%）。

**证明了什么**：
1. **PSN Mapping（弹性）利用率虽非最高，但与最优基线 FIFO 相差 ≤ 5%**（最坏 256B 差 4.46pp，最好 4096B 差 0.36pp），且**优于 Chained Hash 和 Balanced Tree**。
2. **PSN(fixed S=4096) 在 256B 崩到 6.18%**（4128B 槽只装 256B）——直接证明「弹性内存槽大小」机制解决了固定内存块空间利用率低下的问题。
3. 弹性 S 收敛到各 MTU 档（block_S 列），槽浪费 = `align16` 填充 + 24B 头 + 12B meta，随 payload 增大而占比趋零。

**代码 / 数据 / 图位置**：
- 代码：`bench/exp2_space.c`、`baselines/baseline.c` 中的 `cache_footprint_bytes()`
- 数据：`out/exp2_space/space_summary.csv`（原始）、`out/exp2_space/exp2_numbers.md`（脚本提取）、`out/exp2_space/resolved_config.json`
- 图：`paper_figures/fig_exp2_space.png` / `.pdf`（@300dpi）

### 1.4 adaptive / exp3 —— 自适应机制验证（单机模拟器）

**实验目的**：在「包长随时间变化」的端到端场景下，验证自适应 resize 的两条规则（A 扩 / B 缩）、双世代切换、以及「S 匹配负载时利用率高、不匹配时浪费」的动态过程。这是论文 Fig. 3 的数据来源。

**单机模拟器设计（`sim/`，4 模块，严格按 spec §4）**：
- `traffic.c`：按阶段表生成 PSN 递增的数据包（阶段边界按「纪元 = N 个包」计）；`pkt_len==0` 表示混合分布，`e3_jitter>0` 时加包长抖动。
- `loss.c`：丢包模型 uniform / Gilbert-Elliott。语义澄清：**丢包发生在网关下游**——网关已缓存该包，故每个包都 `conn_store`，只有丢的包进 NAK。
- `nak.c`：延迟 `NAK_DELAY` 后把丢失 PSN 汇总成 GBN 区间或 SR 集合，统计 `nak_n / nak_ns_total / bytes_retrans / hit / miss`。
- `sim_main.c`：串联三者 + `conn_store`/`conn_lookup` + 每纪元末批量摊销 lookup 基准 + 落盘全部 trace（S_trace / utilization_trace / overflow_trace / latency_trace / overhead / resize_events / metrics）。

**已完成子实验**（`out/exp3_*`）：

**(a) exp3_phased —— 阶段包长 + S 阶梯（Fig. 3）**
- 阶段表 `{4×4096, 12×1024, 2×4096, 12×1024}`。
- resize 事件（`resize_events.csv`）：
  - epoch 5：`shrink 4096→1024`（4096 阶段结束、1024 阶段开始，规则 B 缩）
  - epoch 16：`overflow_grow 1024→4096`（moved 2048，4096 阶段回来，紧急路径扩）
  - epoch 25：`shrink 4096→1024`（再次缩）
- 利用率（`utilization_trace.csv`）：MTU 阶段（4096B）`util_adaptive = util_static ≈ 98.94%`（S=MTU 恰好匹配）；**<MTU 阶段（1024B）adaptive = 95.88% vs static = 24.73%**（static 兜底 MTU=4096 造成大量浪费）。
- 图：`paper_figures/fig3_adaptive.png` / `.pdf`（双面板：(a) S 阶梯 + 阶段底纹 + resize 事件标注；(b) 利用率 adaptive vs static + 95% 参考线）。

**(b) exp3_mixed —— 混合负载（阈值路径 grow）**
- 阶段表 `{6×1024, 40×混合}`，混合 = 3% 大包 4096 + 97% 小包 1024。
- resize 事件：epoch 4 `shrink 4096→1024`；epoch 7 `grow 1024→4096`（moved 311，**规则 A 阈值路径**——3% 大包 307 条落在 (256,2048)，`ovf_count≥256` 先触发阈值扩而非紧急扩）。

**(c) exp3_hitmiss_d{2,5120,10240,20480} —— NAK 延迟扫描（命中/未命中曲线）**
- 固定 `sim_loss_rate=0.02`，扫 `sim_nak_delay` ∈ {2, 5120, 10240, 20480}。
- 结果（`metrics.csv` 的 hit/miss）：
  - d2、d5120：`miss = 0`（延迟 < 窗口 N=10240，包未被淘汰 → 全命中）。
  - d10240：`miss ≈ 1/epoch`（延迟 = 窗口边界，偶发滑出）。
  - d20480：`miss` 交替 0 与 ~200+（延迟 = 2 个窗口，包在 NAK 到达前已被淘汰）。
- **证明**：缓存深度 N 必须 ≥ in-flight 窗口（带宽延迟积），否则 NAK 延迟超过窗口时命中率塌陷——支撑「N = 重传窗口长度」这一定义。

**(d) exp3_n{1024,4096,10240} —— ring_n 扫描**
- 不同 N 下机制照常工作（`metrics.csv` 中 hit 计数随窗口变小而减小，miss 恒 0）。

> 注：`out/exp3_hitmiss_*` / `exp3_n*` / `exp3_mixed` 目录内的 `resolved_config.json` 是**较早的配置快照**（其中 `e1a_payload_list=[64,1024,4096]`、`e2_pktsize_n=10`、`hash_nbuckets=4096`、`e2_fixed_l=1024` 等与当前 `config.h` 不一致）。这些子实验只依赖 `ring_n / sim_nak_delay / e3_phases / sim_loss_rate / sim_seed`（均未变），故结果仍有效；仅提醒：该文件里的实验预设字段不是当前最新值。

## 3. 代码设计：机制 + 三个基线

### 3.1 我们机制的代码（`src/` + `include/`）

#### (1) `include/dynblock.h` —— 数据模型 + 接口

| 结构 | 大小 | 含义 |
|---|---|---|
| `struct mem_block_header` | 24 B | 数据包头：`data_len(4) + _pad0(4) + recv_stamp(8) + psn(4) + _pad1(4)`；`_Static_assert == 24`。与 260912 旧实现逐字一致 |
| `slot_meta_t` | 12 B | 槽元数据：`psn(4) + len(2) + flag(1) + gen(1) + ovf_idx(4)`（自然 12B，不加 pad） |
| `pool_t` | — | 一代池：`base/N/S/stride/gen/use_mmap` |
| `ovf_entry_t` | 16 B | 溢出项：`psn/len/used/pad/blk` |
| `conn_t` | — | 连接全部状态：`N/S`、`cur/old` 双池、`meta[N]`、`ovf[ovf_cap]`、纪元/streak 计数器、全部统计、resize 事件日志 `rev[128]` |

关键内联函数：`phi(psn) = (psn & 0xFFFFFFu) % N`；`stride_of(S) = align16(24+S)`；`slot(p,i) = base + i*stride`；`payload_of = slot + 24`；`pool_for(gen)`；`psn_newer(a,b)`（24-bit 模序）；`hdr_set`（真写包头）；锁 `spin_*` 是 no-op（单线程，论文不声称并发性能）。

#### (2) `src/dynblock.c` —— 核心算法体

| 函数 | 职责 |
|---|---|
| `conn_init` | `N=ring_n`、`S=ceil_class(mtu或fallback)`、分配 cur 池 + `meta[N]` + `ovf[ovf_cap]` |
| `conn_store` | `Φ` 定位 → `order_guard` 检查（旧包丢弃）→ `evict_occupant`（位置淘汰，O(1)）→ `len≤S` 进环 memcpy / 否则溢出（`ovf_alloc`，满则 `grow_locked` 再试，仍满则 drop）→ 每满 N 个 store 触发 `check_and_maybe_resize` |
| `conn_lookup` | `Φ` + 槽读 + `psn` 比较；环内走 `pool_for(gen)`，溢出走 `ovf[idx]` |
| `conn_retransmit_range/set` | GBN 连续区间 / SR 离散集合的定位 + memcpy |
| `check_and_maybe_resize` | 规则 A（扩）/ 规则 B（缩）+ 纪元统计重置 + 观测快照 |
| `gen_switch` | 双世代零迁移切换（分配新池、旧池挂 old、O(1) 计数） |
| `release_old_if_drained` | 旧池 `old_live==0` 时释放 |
| `drain_overflow` | 扩后把溢出包搬回环内（目标槽校验 + 超上限残留 `n_drain_residual`） |
| `grow_locked` | 紧急扩（假定已持锁） |
| `rev_log` | resize 事件日志（实验三 resize_events.csv 数据源） |
| `conn_force_check` | 管理面手动重评估 |

#### (3) `src/pool.c` —— 内存层

- `pool_alloc`：`mmap(MAP_NORESERVE)` 惰性提交（`cfg.pool_use_mmap=1`），失败回落 `malloc`。
- `pool_free`：按 `use_mmap` 选 `munmap` 还是 `free`，幂等。
- `ovf_alloc`：溢出块 `malloc(align16(24+len))` + 写头；`ovf_release`：free + 复用；`ovf_scan_max`：O(OVF_CAP) 扫最大溢出包长（只在规则 A 调用）。

#### (4) `src/config.c` + `include/config.h` —— 唯一配置

- `cfg_t` 集中所有机制参数 + 实验预设。纪律：**任何被 cfg 读取的字段必须 (1) 在 `config.h` 声明、(2) 在 `cfg_default()` 赋值、(3) 在 `cfg_dump_json()` 落盘**，三者由 `FIELDS[]` 字段表同源维护。
- `cfg_selftest`：`dump → load → memcmp` 断言三者逐字节一致（含字段个数 == N_FIELDS）。
- `cfg_override_cli`：`--key=value` 覆盖任意字段（数组用逗号，`--e3-preset=default|mixed` 等枚举）。
- 关键参数：`ring_n=10240`、`sc_new` 27 档、`ovf_cap=2048`、`ovf_thresh=256`、`hdr_sz=24`、`k_dwell=2`、`j_quiet=4`、`shrink_gamma=0.75`、`hist_decay=8`、`fallback_mtu=4096`、`hash_nbuckets=16384`、实验预设（e1a/e1b/e2/e3/模拟器）。

#### (5) `src/util.c` + `include/util.h` —— 计时 / 随机 / 统计

- 裸 `rdtsc`（无 lfence/rdtscp，避免 VM exit 噪声）；`tsc_calibrate`（CLOCK_MONOTONIC 对 ~100ms 窗标定 `ticks_per_ns`）；`tsc_cross_validate`（rdtsc vs wall 偏差）。
- `xorshift32`（13,17,5，每 rep 独立 seed）；`align16`；`ceil_class`（最小档 ≥ x）。
- 统计：`mean/std`（样本 n-1）、`median/pct`（nearest-rank inverted CDF，与 numpy `percentile(method="inverted_cdf")` 逐值一致）。
- `csv_header/csv_row_*`、`warm_allocator`（预热 malloc 尺寸类）、`g_sink`（抗 DCE）。

### 3.2 三个基线缓存方法（`baselines/baseline.h` + `baseline.c`）

统一接口 `b_cache_t`（每个方法实现同一组 ops + 计数器 `n_malloc/n_cmp/n_resize/n_live`）：

```
store(psn, payload, len) / retrieve(psn,&len) / retrieve_range(start,count,...) / retrieve_set(psns,n,...) / destroy
```

**节点结构**（统一复用 `mem_block_header` 24B 头，与机制同构）：
- `fifo_node` = next(8) + hdr(24) = **32 B** + payload（`_Static_assert == 32`）
- `hash_node` = next(8) + hdr(24) = **32 B** + payload
- `avl_node` = l(8) + r(8) + **p(8，父指针)** + h(4) + hdr(24) = **56 B** + payload（`_Static_assert == 56`；比旧实现 48B 多一个父指针，供 `avl_remove_ptr` 的 O(1) 指针摘除）

**① FIFO Queue**
- 无界 `make_fifo()`：每 store 尾插一个 `malloc(sizeof+len)` 节点、永不 free；`retrieve` 从头线性扫描 O(N)。
- 有界 `make_fifo_bounded(cap, pl)`：预分配节点池（复用首 8B 作 free-list）+ 容量 cap + 满则淘汰 head（FIFO 滑动）。store 路径零 malloc。

**② Chained Hash**
- 无界 `make_chained_hash(nb)`：16384 桶 + Knuth 乘法哈希 `(psn*2654435761u) >> (32-14)` 取高位；每 store 头插 `malloc`；`retrieve` 桶查找 + 链扫描 O(1) 平均（高常数指针追逐）。
- 有界 `make_chained_hash_bounded(cap, nb, pl)`：预分配节点池 + `slot_owner[cap]` 数组；**位置淘汰 `slot = psn % cap`**（与 dynblock Φ 同一 eviction 语义，顺序到达下即 FIFO），从桶链摘下旧节点 + 复用。

**③ Balanced Tree**
- 无界 `make_balanced_tree()`：标准 AVL（rot_r/rot_l/avl_balance + 父指针维护）；`retrieve` 二分下降 O(log N)。
- 有界 `make_balanced_tree_bounded(cap, pl)`：预分配节点池 + 插入序 FIFO 环队列 `fifo_node[cap]`；满则淘汰最早插入者，`avl_remove_ptr` 按节点指针 O(1) 定位 + 双子树后继物理顶替（零数据拷贝）摘除。

**对照 / 适配器**：
- `make_dynblock(cfg, mtu)`：把 `conn_t` 包成 `b_cache_t`（我们的方法）；`dynblock_store` 统计溢出 malloc / resize 增量到 `bc->n_malloc/n_resize`。
- `make_index_only(N)`（对照 E）：只算 `Φ` + 一次槽写/读，不拷贝 payload，给出位置映射不可约成本。
- `cache_footprint_bytes(bc)`：exp2 用的满窗分配总量（池 + 索引/桶 + 元数据，`sizeof` 实测）。
- `baseline_tree_verify(bc)`：AVL 不变式校验（中序严格升序 + |BF|≤1 + 父指针一致），smoke 用。

### 3.3 模拟器（`sim/`）

### 3.4 自测 / 冒烟（`bench/selftest.c` + `baseline_smoke.c`）

- `selftest.c`：`cfg_selftest`（dump→load→memcmp）+ pool 层（mmap/malloc 两路径、溢出块、pool_free 幂等）+ 算法 A1..A17（phi 一致、24-bit 回绕、O(1) 性质、0 malloc、live 不变量、双池排空、grow/drain、shrink、lookup 不删、order_guard、drain 不覆盖、超上限残留、防振荡护栏、MTU 建环、SC_NEW 代数、drop 路径）+ guard 微测量 + rdtsc 交叉验证。
