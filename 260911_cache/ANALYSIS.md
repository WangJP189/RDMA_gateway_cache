## 1. 实验一：时间开销（查找延迟）

### 1.1 查找延迟 P50（N = 10240，单位 ns）

| 方法 | 随机访问 P50 | 顺序访问 P50 |
|------|------------:|------------:|
| FIFO Queue | 2080 ns | 2060 ns |
| Chained Hash | 17.7 ns | 9.0 ns |
| Balanced Tree | 33.1 ns | 16.4 ns |
| **PSN Mapping（本文）** | **9.0 ns** | **8.3 ns** |

### 1.2 中位延迟随缓存占用 N 增长（scaling，N=10240 时）

| 方法 | P50 @ N=10240 | 随 N 增长趋势 |
|------|--------------:|--------------|
| FIFO Queue | 2096.9 ns | **线性** O(n) |
| Chained Hash | 18.0 ns | 平（近似 O(1)） |
| Balanced Tree | 32.7 ns | **对数** O(log n) |
| **PSN Mapping** | **9.0 ns** | **平线 O(1)** |

### 1.3 解读

- **PSN Mapping 最快**：P50 ≈ 9ns，是哈希的 ~1/2、树的 ~1/3、FIFO 的 ~1/230。
- **延迟不随 N 增长**：这是"复杂度曲线"最有力的一张图（`scaling.png`）——
  FIFO 线性爬升、树对数爬升、PSN 平线。哈希虽也是平线，但比 PSN 慢且**无序**
  （哈希查找 O(1) 但无法按序提取连续 PSN 区间）。
- **按序提取（range）**：PSN Mapping 每包 ~3.3ns，与哈希相当（~3.3ns）、
  远优于树（~121ns）与 FIFO（~32ns）。这是 PSN 映射"按序存储"的红利。

## 2. 实验二：空间开销（空间利用率）

### 2.1 空间利用率总表（% = payload / allocated，越大越好；N = 10240）

| 包大小 L (B) | FIFO | Chained Hash | Balanced Tree | PSN 固定5KB | **PSN 动态** | Contiguous 下界 |
|-------------:|-----:|-------------:|--------------:|------------:|-------------:|----------------:|
| 64           | 72.7 | 48.8 | 44.4 | 1.2 | 61.5 | 72.7 |
| 128          | 84.2 | 65.6 | 61.5 | 2.5 | 76.2 | 84.2 |
| 256          | 91.4 | 79.2 | 76.2 | 5.0 | 86.5 | 91.4 |
| 512          | 95.5 | 88.4 | 86.5 | 10.0 | 92.8 | 95.5 |
| 1024         | 97.7 | 93.8 | 92.8 | 20.0 | 96.2 | 97.7 |
| 2048         | 98.8 | 96.8 | 96.2 | 39.9 | 98.1 | 98.8 |
| 4096         | 99.4 | 98.4 | 98.1 | 79.9 | 99.0 | 99.4 |

### 2.2 多流缓存（环形数组 80KB/连接 摊销；L=1024）

- **连接数 K 变化（每连接满载 10240 包）**：利用率恒为 **96.2%**（K=1/8/64/256 不变）。
  → 环形数组固定开销占比与 K 无关，多流下空间效率不劣化。
- **占用深度 npp 变化（1 条连接）**：npp=256→74.4%，512→84.2%，1024→90.1%，
  2048→93.4%，4096→95.2%，10240→96.2%。
  → 环形数组 80KB 的每包摊销从 320B 降到 8B，被充分摊薄。

### 2.3 解读

1. **固定 5KB 块是空间瓶颈（现状的痛点）**：对 64B 小包利用率仅 **1.2%**，
   浪费 99%；直到 4096B 才回升到 80%。这就是动态块机制要解决的问题。
2. **动态块机制（本文新机制）**：把每包开销从 5120B 压到 `header(24B) + 对齐(≤16B)`，
   利用率随包大小单调爬升（61.5% → 99.0%），**最终逼近 contiguous 下界（99.4%）**，
   差距仅 ~0.4 个百分点。
3. **相对其它方法**：哈希/树因每包一个节点（含 next/left/right 指针）而中等偏下
   （小包时 44%~49%）；动态 PSN 映射在 128B 以上普遍优于哈希/树。
4. **"以空间换时间"的量化代价**：PSN 映射唯一比 FIFO 多花的空间是环形数组
   `10240×8B = 80KB/连接`（FIFO 用 N×8B 的可变指针数组）。满载时二者相等；
   轻载时这 80KB 是固定成本——多流实验量化了它如何随占用深度被摊薄。

### 2.4 诚实性说明（正文要写）

- 64B 小包时，FIFO（72.7%）略高于动态 PSN（61.5%）：原因是 `mem_block_header`
  因字段对齐占 24B（含 `recv_stamp` 老化时间戳），比 FIFO 内联的 16B 元数据
  （psn/len/stamp）多 8B 对齐填充。这是结构对齐的常数差，不是方法本质劣势，
  且 PSN 映射换来了 O(1) 查找 + 按序存储。
- 绝对字节/纳秒值受虚拟机影响，结论取相对差异与曲线形态。

## 4. 论文结论要点（供作者组织成文）

1. **方法**：`ring_index = psn % RING_BUFFER_SIZE` 直接下标，O(1) 存储/查找 + 按序
   存储与提取，把传统方法"上层整理乱序包"的负担下放到底层映射。
2. **时间**：查找 P50 ≈ 9ns，且不随缓存占用 N 增长（对照 FIFO 线性、树对数）。
3. **空间**：配合"按包大小动态分配内存块"，利用率随包大小爬升并逼近
   contiguous 下界；固定 5KB 块的浪费问题被解决。
4. **代价**：环形数组 80KB/连接（以空间换时间），多流/满载下被摊薄到可忽略。
5. **不足**：仅软实现/仿真，未在真实 RDMA NIC 验证；绝对值受虚拟机影响。
