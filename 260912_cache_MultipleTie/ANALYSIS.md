## 0. 实验环境与复现

- 环境：Ubuntu 24.04 x86_64 虚拟机（单台 VMware），gcc `-O2 -Wall -std=gnu11`，
  Python3 + numpy/matplotlib。
- 三个基准均为**单机微基准**，纯 C 单文件，无第三方依赖。
- 时间度量用 `rdtsc` 批量（B=128 包）摊薄 VM 的 `rdtscp/lfence` VM-exit 噪声，
  `calibrate_tsc` 标定 TSC→ns；随机序列用 xorshift32 固定种子（0x9E3779B9），可复现。
- 分档动态块档界：`{256, 512, 1024, 2048, 4096}`；块大小 = align16(header 24B + 档界)。

## 1. 实验一：时间开销（查找延迟）

### 1.1 查找延迟 P50（N = 10240，单位 ns）

| 方法 | 随机访问 P50 | 顺序访问 P50 |
|------|------------:|------------:|
| FIFO Queue | 2170 ns | 2198 ns |
| Chained Hash | 18.7 ns | 9.7 ns |
| Balanced Tree | 34.1 ns | 17.0 ns |
| **PSN Mapping（本文）** | **9.7 ns** | **9.0 ns** |

### 1.2 中位延迟随缓存占用 N 增长（scaling）

| 方法 | P50 @ N=512 | P50 @ N=10240 | 趋势 |
|------|------------:|--------------:|------|
| FIFO Queue | 82.8 ns | 2158.8 ns | **线性 O(n)** |
| Chained Hash | 9.4 ns | 18.7 ns | 平（近似 O(1)，大 N 略升） |
| Balanced Tree | 21.4 ns | 33.7 ns | **对数 O(log n)** |
| **PSN Mapping** | **9.7 ns** | **9.0 ns** | **平线 O(1)** |

### 1.3 解读

- **PSN Mapping 最快**：P50 ≈ 9ns，是哈希的 ~1/2、树的 ~1/3、FIFO 的 ~1/240。
- **延迟不随 N 增长**：`scaling.png` 是最有力的一张图——FIFO 线性爬升、树对数爬升、
  PSN 平线。哈希虽也近似平，但（a）比 PSN 慢、（b）**无序**（无法按序提取连续 PSN 区间）。
- **优化幅度（相对 FIFO）**：`(2158.8 - 9.0)/2158.8 ≈ 99.6%`，即查找快 ~240×。

> 分档动态 avg = `align16(header 24 + 档界)` + 每包摊固定数组开销 ~41B
> （= 标记 1B + 5 根环 8B×5×10240/N）。

### 2.3 多流摊销（任务 G；L = 1024）

- **连接数 K 变化（每连接满载 10240 包）**：分档动态利用率与 K 无关，
  ~93.3%（简单动态 ~96.2%），多流下空间效率不劣化（固定数组开销与 K 线性同增）。
- **占用深度 npp 变化（1 条连接）**：npp 越小，410KB 固定数组每包摊销越大，利用率越低；
  满载 npp=10240 时摊到 ~41B/包，利用率回到 ~93%。

### 2.4 解读

1. **固定 5KB 块是空间瓶颈（现状痛点）**：64B 小包利用率仅 1.2%（浪费 99%），
   直到 4096B 才 80%。这是动态块机制要解决的问题。
2. **简单动态块（260911 方案）空间最优**：每包 `header+payload` 对齐 16B，利用率
   61.5% → 99.0%，几乎贴着 contiguous 下界。但它按包大小 `malloc`，有分配器开销、
   外部碎片、块大小不一破坏 cache 局部性——这些是**空间表看不出来**的隐藏成本。
3. **分档动态块（本文）空间"够用且可预测"**：档界附近（256/512/1024/2048/4096）
   利用率 78%~98%；非 2 幂（1280/1400/1500）取整到 2048 档，利用率 60%~71%，
   低于简单动态 ~97%，但**仍比固定 5KB 高 2.4×~16×**（如 1280B：60.3% vs 25.0%，
   64B：19.5% vs 1.2%）。
4. **分档换来了内存管理确定性**：每档同尺寸块 + free-list，稳态几乎不再 malloc
   （实验三实测复用率 94.6%），无外部碎片、cache 更规整——这是空间表外、行为实验里
   才体现的收益。
5. **诚实性**：分档的固定数组开销 410KB/连接（5× 单环 80KB），这是"分档"的结构代价；
   简单动态只有 80KB。多流实验量化了它随占用深度被摊薄的过程。

## 3. 实验三：存/取行为（跨 6 种缓存方法对比）

参数：N=10240 包，L=1024B，批大小 B=128，批数 R=100，种子 0x9E3779B9。
对比 `fifo`（链表 O(n)）、`chained_hash`（哈希 O(1) 无序）、`balanced_tree`
（AVL O(log n)）、`psn_fixed`（PSN 单环 + 固定 5KB）、`psn_dynamic`（PSN 单环 +
逐包 malloc）、`psn_tiered`（**PSN 分档动态块，本文**）。

### 3.1 延迟总表（P50，单位 ns）

| 方法 | store 顺序 | store 乱序 | 按序取回 | 命中取回 | 丢包判定 | 控制面 store(64B) | 比较/取回 |
|------|----------:|----------:|--------:|--------:|--------:|-----------------:|----------:|
| FIFO 队列 | 1666 | 1580 | **8806** | 8926 | **19286** | 256 | **5120.5** |
| 链式哈希 | 1579 | 1591 | 44.6 | 53.9 | 32.8 | 255 | 1.0 |
| 平衡树 | 1710 | 1995 | 110 | 96.2 | 86.0 | 494 | 12.6 |
| PSN 固定 5KB | **7808** | **7708** | 53.2 | 63.3 | 31.3 | 281 | 0.0 |
| PSN 简单动态 | 1586 | 1604 | 46.9 | 53.9 | 32.1 | 99.3 | 0.0 |
| **PSN 分档动态（本文）** | **1564** | **1604** | **46.1** | 63.3 | 37.5 | **83.7** | **0.0** |

### 3.2 端到端延迟（store 乱序 mean + 按序取回 mean，单位 ns）

| 方法 | store 乱序 mean | 按序取回 mean | 端到端/包 | 相对本文 |
|------|----------------:|--------------:|----------:|---------:|
| FIFO 队列 | 1657 | 9048 | 10705 | **7.2×** |
| 链式哈希 | 1740 | 51.8 | 1792 | 1.2× |
| 平衡树 | 1757 | 124 | 1881 | 1.3× |
| PSN 固定 5KB | 7544 | 61.9 | 7606 | **5.1×** |
| PSN 简单动态 | 1432 | 53.6 | 1486 | 1.0× |
| **PSN 分档动态（本文）** | **1434** | **52.8** | **1487** | **1.0×（最快）** |

### 3.3 分配行为（覆盖写稳态）

| 方法 | 覆盖写次数 | malloc 次数 | malloc/store |
|------|-----------:|------------:|-------------:|
| PSN 固定 5KB | 12800 | 12800 | 1.0 |
| PSN 简单动态 | 12800 | 12800 | 1.0 |
| **PSN 分档动态（本文）** | 12800 | **0** | **0.0** |

### 3.4 解读

1. **零整理（本文相对 FIFO 的核心优势）**：乱序 store 后按序取回，FIFO 需
   **O(n) 扫描 + 5120.5 次 PSN 比较 = 8.8µs**，而本文 **0 次比较 = 46ns**，快 ~190×。
   这是"底层确定、上层零整理"的直接证据——比较次数 0 意味着取回阶段**无需任何排序**。
2. **O(1) 且与访问模式/丢包率无关**：本文 store 顺序/乱序基本一致（1564/1604ns）、
   取回命中/丢包判定基本一致（46/38ns）；丢包率 0%→10% 判定延迟平直（图 3d）。
3. **store 的控制面开销最低（本文相对动态/固定的优势）**：用 64B 负载隔离出
   「分配器 + 索引 + 指针」的真实每包开销——本文 **83.7ns** < 简单动态 99.3ns
   （省掉逐包 malloc）< 固定 281ns（5KB malloc）< 树 494ns（log n 插入+旋转）。
   全负载 L=1024 时 store 受 memcpy（~1.5µs）支配，固定 5KB 因大块 malloc 慢 **5×**。
4. **确定性内存（本文相对简单动态的核心优势）**：稳态覆盖写 12800 次，本文
   **0 次 malloc**（分档池 free-list 全复用），而简单动态/固定各 12800 次——消除了
   分配器开销、外部碎片、以及 malloc/free 对 cache 局部的破坏。
5. **诚实代价**：本文 retrieve ~46ns 略高于单环 PSN 查找（~9ns，实验一），因为分档
   查找 = 读标记数组 + 读分档环 = **2 次数组访问**（vs 单环 1 次），5 根环共 400KB
   超出 L2。绝对量仍 ~46ns 且平线，与 FIFO（µs 级）不可比。

## 5. 论文结论要点（供作者组织成文）

1. **方法**：`ring_index = psn % RING_BUFFER_SIZE` 直接下标 → O(1) 存储/查找 + 按序
   存储，把传统方法"上层整理乱序包"的负担下放到底层映射（任务 B 零整理为直接证据）。
2. **分档动态块**：用「档位标记数组 + 分档环形数组」把内存块按 2 幂档界分档，每档
   slab 式 free-list 复用（稳态覆盖写 **0 次 malloc**），解决简单 malloc 的分配器
   开销/外部碎片/cache 局部性三问题，同时保持 **2 次数组访问的 O(1) 查找**。
3. **时间**：查找 P50 ≈ 9ns（单环，实验一），分档取回 ≈ 46ns（实验三，2 次数组访问），
   二者均不随 N/丢包率增长；端到端（store+取回）本文 1487ns 最快，比 FIFO 快 7.2×、
   比固定 5KB 快 5.1×。
4. **空间**：分档在档界附近利用率 78%~98%、非 2 幂取整后 60%~71%，**始终优于固定
   5KB 块（1.2%~80%）**；比简单动态略低，但换来内存管理确定性。
5. **代价**：5× 固定数组开销（410KB/连接）与 2 幂取整（以空间换时间 + 换内存管理）。
6. **不足**：仅软实现/仿真，未在真实 RDMA NIC 验证；绝对值受虚拟机影响，结论取相对差异。
